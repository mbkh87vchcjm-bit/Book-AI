# مِداد ٢ — مساعد مراجع محلي على أندرويد

مِداد تطبيق Android عربي لتنظيم المراجع في دفاتر منفصلة، والبحث في PDF (نصي أو مصوّر) والملفات النصية، واقتباس الجمل المتعلقة بالسؤال مع اسم المرجع ورقم الصفحة. لا يحتاج حسابًا ولا إنترنت، ولا يطلب التطبيق صلاحية الإنترنت أو صلاحيات التخزين العامة.

> **هذه نسخة قابلة للتجربة، وليست إصدارًا مُختبرًا على هاتف فعلي.** حُزمت لمعالجات **ARM64** فقط وعلى Android 9 (API 28) أو أحدث. لا تحتوي على نموذج لغوي ولا تحتاج استيراد نموذج.

## ما يفعله التطبيق فعلًا

| الطلب | ما يقدّمه مِداد ٢ |
| --- | --- |
| إضافة ملزمة أو مرجع | PDF نصي، PDF مصوّر، TXT/Markdown، أو نص ملصق مباشرة. لكل دفتر مصادره ومحادثته. |
| إظهار المصدر | كل جملة معروضة تأتي من نص المرجع نفسه، مع اسم الملف ورقم الصفحة ومقتطف. إن كان النص مقروءًا من صورة يظهر تنبيه صريح. |
| البحث عن جواب | ينتقي جملًا من صفحات مراجعك المرتبطة بأسئلة السؤال، ويعرضها كاقتباسات مع أرقامها. |
| الحساب | يجري العمليات الحسابية ويحل المعادلات الخطية البسيطة (`2س+3=11`) بقواعد مبرمجة، ويوضح أن الناتج **حساب محلي وليس من مرجع**. |
| التلخيص | ملخص **اقتباسي** من جمل مختارة (حتى ٥ جمل)، وليس صياغة جديدة، ولا يشمل المرجع كاملًا. |
| القيود | «المصادر فقط»، إيقاف الحساب، إيقاف قراءة الصور، وتحديد عدد الجمل. |

### ما لا يفعله، بوضوح

مِداد ٢ **ليس** ChatGPT ولا NotebookLM. لا يولّد فقرات جديدة، ولا يعيد صياغة أو يشرح بمفرده، ولا يجيب عن سؤال معرفي عام من ذاكرته، ولا يستنتج حلولًا لمسائل كلامية في الفيزياء أو الرياضيات. عند عدم وجود نص مناسب يقول ذلك بدل التخمين. بناء نموذج لغوي عام بهذا المستوى يحتاج بيانات تدريب ضخمة وحوسبة غير متاحة داخل تطبيق هاتف، ولذلك اخترنا محركًا صغيرًا يمكن التحقق من كل جملة فيه.

## التثبيت والاستخدام

1. انقل [`release/Midad-2.0.0-local.apk`](release/Midad-2.0.0-local.apk) إلى الهاتف وافتحه. قد يطلب Android السماح بالتثبيت من مصدر الملفات الذي تستخدمه.
2. افتح مِداد واضغط **أضف مصدرك الأول**، ثم اختر PDF أو TXT أو Markdown.
3. انتظر انتهاء الاستخراج. الصفحات المصوّرة تُقرأ محليًا (حتى ١٥ صفحة لكل ملف) وتظهر نافذة بالملاحظات.
4. اكتب سؤالك. تظهر الإجابة كجمل مقتبسة مع أرقام، وتحتها بطاقات المصادر (اسم الملف ورقم الصفحة).
5. اضغط بطاقة المصدر لرؤية المقتطف، ثم **عرض نص الصفحة** لرؤية صورة الصفحة والنص الكامل.
6. إن أخطأ القارئ في كلمة، اضغط **تصحيح نص الصفحة** وقارن بالصورة ثم اكتب النص الصحيح. تُستخدم النسخة المصححة في الأسئلة اللاحقة.
7. **الإعدادات والتحكم** لضبط القيود المذكورة أعلاه.

## قراءة صفحات PDF المصوّرة

الطريقة ليست نموذجًا مدرَّبًا، بل تعرّف على الكلمات بخطوط مطبوعة:

- يرسم التطبيق آلاف الكلمات من قاموس محلي (٢٥ ألف كلمة عربية و١٥ ألف إنجليزية) بأربعة خطوط مطبوعة، ويقارن كل كلمة في الصورة بأقرب قالب بعد قصّها من الصفحة.
- عند الشك يظهر الرمز `□` بدل تخمين كلمة، ويُنبَّه المستخدم بذلك.
- يعمل مع **النص المطبوع النظيف** بالخطوط المشمولة (IBM Plex Sans Arabic، Noto Naskh Arabic، Amiri، DejaVu). لا يتعامل مع الخط اليدوي، ولا مع الصور المائلة أو المنخفضة الجودة أو الرسوم والجداول، ولا يضمن كل الكلمات.
- الحد ٣٥٠ كلمة لكل صفحة و١٥ صفحة مصوّرة لكل ملف؛ تُتجاهل الزيادة مع تنبيه.
- النص المقروء من الصور **يحتاج مراجعة بشرية** قبل الاعتماد عليه، ولهذا تُحفظ صورة الصفحة مع النص لتصحيحه.

## الحدود والخصوصية

- ملف PDF المحمي بكلمة مرور غير مدعوم؛ أزل الحماية قبل الاستيراد.
- حد الملف الواحد ٦٠ ميغابايت، وحد النص المستخرج ٣ ملايين حرف، وحتى ٥٠٠ صفحة لكل PDF.
- البحث يعتمد على تطابق الكلمات (مع تجذيع عربي بسيط) لا على فهرس دلالي؛ قد يفوّت صياغات مرادفة.
- التلخيص يأخذ جملًا مختارة من صفحات محددة، ولا يضمن تغطية المرجع.
- الحساب يدعم `+ - × ÷ % ^` والأقواس والمتغير `س` في معادلة خطية واحدة، ويرفض غير ذلك صراحة.
- تحفظ البيانات (النصوص المستخرجة والصور المصغّرة والمحادثات) محليًا داخل مساحة التطبيق؛ لا يُحفظ ملف PDF الأصلي ولا يُرسل شيء إلى أي جهة. النسخ الاحتياطي معطّل. حذف التطبيق يمسح البيانات.
- APK موقّع بمفتاح **تطوير**. للتحديث فوق نسخة مثبتة يجب التوقيع بالمفتاح نفسه؛ إزالة النسخة المثبتة لتغيير المفتاح ستمسح بياناتها.
- التطبيق غير مُختبَر على هاتف أو محاكي Android. اختُبرت موارده على Chromium وNode على الحاسوب.

## للمطورين

المكوّنات:

- `app/src/main/assets/web/engine.js` — بحث محلي في المقاطع، وربط كل نتيجة بصفحتها.
- `app/src/main/assets/web/local-answer.js` — انتقاء الجمل والاقتباس ومحلّل الحساب المقيّد.
- `app/src/main/assets/web/ocr.js` — معالجة الصورة وتقطيع السطور والكلمات ومطابقة القوالب.
- `app/src/main/assets/web/ocr/templates.bin` و`vocabulary.json` — جدول القوالب المولَّد محليًا والقاموس.
- `app/src/main/assets/web/app.js` — الواجهة والحفظ والاستيراد والتصحيح.
- `app/src/main/java/com/midad/bookai/MainActivity.java` — WebView محلي وتخزين ذري وSAF.

التراخيص في [`third_party/`](third_party/) ومضمّنة داخل APK في `assets/licenses/`.

### الاختبارات

```bash
npm test                 # 17 اختبارًا: البحث، الاقتباس، الحساب، سلامة جدول القوالب
npm ci
CHROMIUM_PATH=/path/to/chromium npm run test:browser
```

اختبارات المتصفح تبني PDF مصوّرًا حقيقيًا من الصور، ثم تختبر الاستخراج والاقتباس ورقم الصفحة وصورة الصفحة والتصحيح والحفظ، إضافة إلى أربعة خطوط وأربعة أحجام، وحالات الملف المحمي والإلغاء والفشل في قراءة البيانات. التشغيل في هذه البيئة:

```bash
NODE_PATH=/home/user/tools/browser/node_modules \
LD_LIBRARY_PATH=/home/user/tools/chromiumlibs/lib \
CHROMIUM_PATH=/tmp/chromium npm run test:browser
```

### إعادة توليد قوالب القراءة

```bash
NODE_PATH=/path/to/node_modules CHROMIUM_PATH=/path/to/chromium node scripts/build-ocr-templates.cjs
```

تُولَّد `templates.bin` (٢٠٠ ألف قالب، نحو ١٤ ميغابايت) من القاموس والخطوط المشمولة؛ لا تُضمّن أوزان نموذج مدرَّب.

### بناء APK

يتطلب JDK 17، وAndroid SDK Platform 34، وBuild Tools 34، و`zip`.

```bash
export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk
scripts/build-apk.sh
```

ينتج `release/Midad-2.0.0-local.apk` ويوقّعه بمفتاح تطوير محلي. للإصدار الحقيقي وفّر `SIGNING_KEYSTORE` و`SIGNING_ALIAS` و`SIGNING_STORE_PASSWORD` و`SIGNING_KEY_PASSWORD` واحفظ المفتاح خارج المستودع.

### بنية الحزمة

اسم الحزمة `com.midad.bookai.local`، والحد الأدنى Android 9 (API 28). لا توجد مكتبات JNI أو أوزان نموذج داخل الحزمة؛ كل ما يلزم للبحث والحساب وقراءة الصور موجود في أصول التطبيق.

## التقييم الفني للمفهوم والتأطير المستقبلي لنماذج LiteRT / MediaPipe LLM والبحث الدلالي

عند تقييم دمج نموذج لغوي محلي فعلي (مثل LiteRT-LM / MediaPipe LLM Inference) والبحث الدلالي (Embedding Model) على نظام Android:

1. **بنية المحرك المحلي والواجهة**:
   - يتطلب تشغيل LiteRT-LM أو MediaPipe Task C++ APIs على Android وجود مكتبات ناتجة ذات امتداد Native (`.so`) مربوطة بـ JNI إلى جانب طبقة C++ Native Wrapper. لا يدعم WebView بمفرده تشغيل نماذج 1B - 3B مباشرة بلغة JavaScript بدون WebGPU المحظور على معظم أجهزة Android WebView.
   - يتطلب الاستدلال الدلالي (Vector Embeddings) نموذجًا محليًا مساندًا (مثل All-MiniLM-L6-v2 أو BERT Arabic Quantized tflite) يُشغّل عبر TFLite C++ Runtime لاستخراج المتجهات وحفظها في قاعدة بيانات متجهات محلية (مثل SQLite Vector / HNSWlib Native).
2. **استيراد النموذج عبر SAF**:
   - يجب استيراد أوزان النموذج (بصيغة `.bin` أو `.task` المكيّفة لـ LiteRT) من التخزين الخارجي بواسطة Android Storage Access Framework (`ACTION_OPEN_DOCUMENT`) لتفادي صلاحيات التخزين العامة وتجنب تضمين أوزان ضخمة (١.٥ إلى ٣ غيغابايت) داخل APK.
3. **متطلبات العتاد والقيود**:
   - الأجهزة المطلوبة: معالج ARM64 مع 6GB - 8GB RAM كحد أدنى ويدعم Vulkan GPU Acceleration.
   - قيود السرعة والذاكرة: تستهلك النماذج أداءً عاليًا من البطارية والذاكرة العشوائية؛ لذلك يُعتمد المحرك الحالي Deterministic Local Extractive Engine كخيار افتراضي سريع ومضمون الخصوصية وموثوق الإسناد كليًا.
